Docus 默认集成 `nuxt-llms`，为大语言模型 (LLM) 准备好你的内容。你的所有文档页面都会被注入，并自动生成和预渲染 `/llms.txt` 与 `/llms-full.txt` 文件。

::note{to="https://docus.dev/llms.txt"}
看看为 Docus 文档自身生成的 `/llms.txt` 文件。
::

## 默认值

以下是用于生成 `/llms.txt` 文件的默认值：

- `domain` → 根据你的部署平台计算得出 (或使用 `NUXT_SITE_URL` 环境变量)
- `title` → 从你的 `package.json` 中提取
- `description` → 从你的 `package.json` 中提取
- `full.title` → 从你的 `package.json` 中提取
- `full.description` → 从你的 `package.json` 中提取

## 自定义

你可以在 `nuxt.config.ts` 中覆盖 LLMs 数据：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  llms: {
    domain: 'https://your-site.com',
    title: '你的站点名称',
    description: '对你站点的简短描述',
    full: {
      title: '你的站点名称',
      description: '对你站点的简短描述',
    },
  },
})
```

### 引导 Agent

你的页面告诉 Agent 你的产品能做什么，却很少告诉它*何时*该选择你——而这正是 Agent 在推荐你之前需要了解的信息。有两个选项可以覆盖这一点：

- `sections` 在生成的页面列表之上添加一组链接，用于指向内容之外的资源 (代码仓库、软件包、API 参考)
- `notes` 在文档末尾添加一个 `## Notes` 块，是放置使用时机指引的理想位置

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  llms: {
    domain: 'https://your-site.com',
    sections: [
      {
        title: 'Developer Resources',
        description: '可供机器读取的入口。',
        links: [
          { title: 'GitHub 上的源码', description: 'Issue 与发布。', href: 'https://github.com/your-org/your-repo' },
        ],
      },
    ],
    notes: [
      '何时使用此库:当你正在构建 X 并希望实现 Y 时。',
      '此库不能替代 Z。若有该需求,请改用 W。',
      '作为 Agent 阅读本文档:在任意页面 URL 后追加 `.md`,或发送 `Accept: text/markdown`。',
    ],
  },
})
```

## 对 Agent 友好的 404

Docus 不会返回 JSON 错误体，而是返回一份简短的 Markdown 文档，列出你的站点实际提供的机器可读入口：

```bash
curl -H "Accept: text/markdown" https://docus.dev/en/does-not-exist
```

```md
---
title: "Page Not Found"
status: 404
---

The page `/en/does-not-exist` does not exist on https://docus.dev.

- [MCP server card: MCP endpoint at https://docus.dev/mcp](https://docus.dev/.well-known/mcp/server-card.json)
- [MCP endpoint (streamable HTTP)](https://docus.dev/mcp)

## Fetching markdown

Any documentation page is available as markdown: append `.md` to its URL
or send `Accept: text/markdown`.
```

这些链接与首页的 `Link` 响应头以及 `/.well-known/api-catalog` 来自同一个注册表，因此该文档绝不会指向不存在的路由：技能条目只在你的站点[发布了技能](/zh-cn/ai/skills)时才会出现，`/llms-full.txt` 也只在启用后才会列出。

响应保留 `404` 状态码，并以 `text/markdown; charset=utf-8` 提供，同时带有 `Vary: Accept, User-Agent`，因此 CDN 绝不会将其与 HTML 版本混淆。

只有明确不会渲染 HTML 的客户端才会收到这份文档。以下情况不受影响：

- **浏览器**：任何接受 `text/html` 的请求仍然渲染主题的错误页面
- **API 客户端**：接受 `application/json` 的请求，或 `/api/` 与 `/mcp` 下的请求，保留默认的 JSON 错误体
- **`fetch()` 与 `$fetch`**：浏览器发起的请求保留默认的 JSON 错误体，因此 `error.data` 仍然可解析

若要恢复默认的错误体：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  agentDiscovery: {
    errors: false,
  },
})
```

## 原始 Markdown 访问

Docus 暴露了一个原始 Markdown 端点，让 AI Agent 无需经过完整的渲染管线即可获取 LLM 就绪的源文件。这减少了 token 消耗，并提升了消费你文档的 AI 工具的响应速度。

### 工作原理

- **端点**:`/raw/<content-path>.md`，与页面 URL 路径相同，只是加上 `.md` 扩展名
- **Content-Type**:`text/markdown; charset=utf-8`，并带有指回 HTML 页面的 `Link` 响应头
- **Frontmatter**：每个文档都以其 `title`、`description` 和 `canonical_url` 开头，且同源链接均为绝对链接，因此页面在脱离你的站点被读取后依然完整可解
- **章节**：指向章节而非页面的路径 (`/raw/zh-cn/getting-started.md`)会重定向到该章节的第一个文档
- **LLMs.txt 集成**:`llms.txt` 中的文档链接会自动重写为 `/raw/...md` 端点，让 Agent 获取精简的 Markdown 而非完整的 HTML

::note{to="/raw/zh-cn/ai/llms.md"}
试着访问本页面的原始 Markdown 版本。
::

### 配置

默认情况下，每个页面都有一个 Markdown 孪生版本。若要将站点的某部分排除在外——例如没有 Markdown 版本的页面树，或你自行提供的独立 `.md` 文档——请扩展 `excludePrefixes`。被排除的路径绝不参与协商，不会出现在任何列表中，并且在原始端点上返回 404：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  agentDiscovery: {
    excludePrefixes: {
      extend: ['/admin'],
    },
  },
})
```

## Markdown 协商

对于索要 Markdown 的 AI Agent 和 CLI 工具，Docus 会在与 HTML 页面相同的 URL 上返回 Markdown。

### 为什么？

Claude Code 这类 Agent 默认发送 `Accept: text/markdown`。以原始 Markdown 响应可以节省大量数据传输和 token。

### 如何实现？

当请求满足以下条件之一时，将获得 Markdown：

- URL 以 `.md` 结尾：`/zh-cn/ai/llms.md` 是 `/zh-cn/ai/llms` 的 Markdown 孪生版本
- 其 `Accept` 头对 `text/markdown` 的偏好高于 `text/html`
- 其 `User-Agent` 是已知的 AI Agent (`ClaudeBot`、`GPTBot`、`PerplexityBot`，以及 [ai.robots.txt](https://github.com/ai-robots-txt/ai.robots.txt) 列表中的其他 Agent)

然后：

- **根路径**:`/` → `/raw/index.md`，当首页是内容文档时返回你的落地页，当首页是 Vue 页面时返回生成的索引，两者都以本站点为 Agent 发布的全部内容列表作为结尾
- **文档页面**:`/{path}` → `/raw/{path}.md`

协商通过一个 Nitro 中间件在开发环境和所有托管平台上运行。在 Vercel 上它还会在边缘运行，因此预渲染页面会在 CDN 缓存收到请求之前就以 Markdown 响应。在其他托管平台上，预渲染页面会先于中间件被返回并保持 HTML:Agent 可以通过 `.md` URL 获取其 Markdown 版本。

### 使用示例

```bash
# 从首页获取 Agent 索引
curl -H "Accept: text/markdown" https://docus.dev/

# 获取文档页面的原始 Markdown
curl -H "Accept: text/markdown" https://docus.dev/zh-cn/ai/llms

# 同一页面,通过其 Markdown 孪生 URL
curl https://docus.dev/zh-cn/ai/llms.md
```

所有这些命令都会返回 Markdown 内容而非 HTML。

### 缓存

同一个 URL 会根据请求返回 HTML 或 Markdown，因此每个响应都带有 `Vary: Accept, User-Agent`。没有它，CDN 可能会向索要 Markdown 的 Agent 返回 HTML 版本，反之亦然——取决于哪一个先进入缓存。

```bash
curl -sI -H "Accept: text/markdown" https://docus.dev/zh-cn/ai/llms | grep -i vary
# vary: Accept, User-Agent
```

## 发现机制

Agent 访问你的站点后，无需阅读文档即可找到站点发布的全部内容：

- `/.well-known/api-catalog`：本站点发布的每份服务文档 ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727))，同时也在首页的 `Link` 响应头中声明
- `/openapi.json`：一份 OpenAPI 文档，描述 Markdown 路由、发现文档和 MCP 端点
- `/sitemap.md`：所有页面的 Markdown 索引，按章节分组，多语言站点上每个语言环境各有一份
- `/.well-known/mcp/server-card.json`:[MCP 服务器](/zh-cn/ai/mcp)端点及其暴露的工具
- `/.well-known/skills/index.json`：你发布的 [Agent 技能](/zh-cn/ai/skills)
- `/robots.txt`：允许每个已知 AI Agent 的分组，并带有 `Content-Signal` 行

所有这些都由 [`nuxt-agent-discovery`](https://github.com/benjamincanac/nuxt-agent-discovery) 模块提供，并通过 `nuxt.config.ts` 中的 `agentDiscovery` 键进行配置。

::tip{to="https://github.com/benjamincanac/nuxt-agent-discovery"}
查看 nuxt-agent-discovery 文档以了解所有选项。
::
