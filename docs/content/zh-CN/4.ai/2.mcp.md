## 关于 MCP 服务器

[Model Context Protocol(MCP)](https://modelcontextprotocol.io/) 是一个开放协议，用于在 AI 应用与文档等外部服务之间建立标准化的连接。

每个 Docus 实例都内置了一个 MCP 服务器，让你的内容为更广泛的 AI 生态做好准备——任何 MCP 客户端 (如 Claude、Cursor、VS Code 等) 都可以连接到你的文档。

### MCP 服务器的工作原理

当 MCP 服务器连接到 AI 工具后，LLM 可以在生成回复的过程中决定调用你的文档工具：

- LLM 可以在生成回复时**主动搜索你的文档**，而不只是在被明确要求时才这样做。
- LLM 会根据对话上下文以及你的文档的相关性，**决定何时使用工具**。
- 每次工具调用都发生在**生成过程之中**，使 LLM 能够将来自你文档的实时信息融入其回复。

例如，当用户提出一个编程问题，而 LLM 判断你的文档与之相关时，它可以搜索你的文档并将这些信息纳入回复，而无需用户明确询问你的文档。

## 访问你的 MCP 服务器

你的 MCP 服务器会自动在文档 URL 的 `/mcp` 路径下可用。

::note
例如，如果你的文档托管在 `https://docs.example.com`，那么你的 MCP 服务器 URL 就是 `https://docs.example.com/mcp`。
::

::note
MCP 服务器会以 `MCP Server` 章节的形式记录在你的 [`llms.txt`](/zh-cn/ai/llms) 中。通过 `llms.txt` 发现你站点的 Agent 可以直接连接，无需任何人将 URL 粘贴到客户端配置中。
::

::note
你的站点还会在 `/.well-known/mcp/server-card.json` 发布一张 MCP 服务器名片。它列出了端点以及服务器暴露的工具、资源和提示词，Agent 无需阅读文档即可找到该服务器。
::

## 禁用 MCP 服务器

如果你想禁用 MCP 服务器，可以在 `nuxt.config.ts` 中进行设置：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  mcp: {
    enabled: false,
  },
})
```

## 内置工具

Docus 开箱即用地提供了两个工具，让任何 LLM 都能发现并阅读你的文档：

### `list-pages`

列出所有文档页面及其标题、路径和描述。AI 助手应先调用此工具来发现可用内容。

| 参数 | 类型              | 描述            |
| --------- | ----------------- | ---------------------- |
| `locale`  | string (可选) | 按语言环境筛选页面 |

### `get-page`

获取指定文档页面的完整 Markdown 内容。

| 参数 | 类型              | 描述                                              |
| --------- | ----------------- | -------------------------------------------------------- |
| `path`    | string (必填) | 页面路径 (例如 `/zh-cn/getting-started/installation`) |

## 安装配置

Docus MCP 服务器使用 HTTP 传输，可以安装到不同的 AI 助手中。

### Claude Code

使用 CLI 命令添加服务器：

```bash
claude mcp add --transport http my-docs https://docs.example.com/mcp
```

### Cursor

:install-button{ide="cursor" label="在 Cursor 中安装" url="https://docs.example.com/mcp"}

或手动在项目根目录创建/更新 `.cursor/mcp.json`:

```json [.cursor/mcp.json]
{
  "mcpServers": {
    "my-docs": {
      "type": "http",
      "url": "https://docs.example.com/mcp"
    }
  }
}
```

### Visual Studio Code

确保你已安装 GitHub Copilot 和 GitHub Copilot Chat 扩展。

:install-button{ide="vscode" label="在 VS Code 中安装" url="https://docs.example.com/mcp"}

或手动创建/更新 `.vscode/mcp.json` 文件：

```json [.vscode/mcp.json]
{
  "servers": {
    "my-docs": {
      "type": "http",
      "url": "https://docs.example.com/mcp"
    }
  }
}
```

### Windsurf

1. 打开 Windsurf，进入 **Settings** > **Windsurf Settings** > **Cascade**
2. 点击 **Manage MCPs** 按钮，然后选择 **View raw config** 选项
3. 添加以下配置：

```json [.codeium/windsurf/mcp_config.json]
{
  "mcpServers": {
    "my-docs": {
      "type": "http",
      "url": "https://docs.example.com/mcp"
    }
  }
}
```

### Zed

1. 打开 Zed，进入 **Settings** > **Open Settings**
2. 打开 JSON 设置文件
3. 添加以下 context server 配置：

```json [.config/zed/settings.json]
{
  "context_servers": {
    "my-docs": {
      "source": "custom",
      "command": "npx",
      "args": ["mcp-remote", "https://docs.example.com/mcp"],
      "env": {}
    }
  }
}
```

## 自定义

由于 Docus 使用 `@nuxtjs/mcp-toolkit` 模块，你可以通过自定义工具、资源、提示词和处理器来扩展 MCP 服务器。

### 添加自定义工具

在 `server/mcp/tools/` 目录中创建新工具：

```ts [server/mcp/tools/search.ts]
import { z } from 'zod'

export default defineMcpTool({
  description: '按关键词搜索文档',
  inputSchema: {
    query: z.string().describe('搜索查询'),
  },
  handler: async ({ query }) => {
    const results = await searchDocs(query)
    return {
      content: [{ type: 'text', text: JSON.stringify(results) }],
    }
  },
})
```

### 添加资源

在 `server/mcp/resources/` 目录中将文件或数据源暴露为 MCP 资源。最简单的方式是使用 `file` 属性：

```ts [server/mcp/resources/changelog.ts]
export default defineMcpResource({
  file: 'CHANGELOG.md',
  metadata: {
    description: '项目变更日志',
  },
})
```

它会自动处理 URI 生成、MIME 类型检测和文件读取。

### 添加提示词

在 `server/mcp/prompts/` 目录中为 AI 助手创建可复用的提示词：

```ts [server/mcp/prompts/migration-help.ts]
import { z } from 'zod'

export default defineMcpPrompt({
  description: '获取版本间迁移的帮助',
  inputSchema: {
    fromVersion: z.string().describe('当前版本'),
    toVersion: z.string().describe('目标版本'),
  },
  handler: async ({ fromVersion, toVersion }) => {
    return {
      messages: [{
        role: 'user',
        content: {
          type: 'text',
          text: `请帮我把代码从版本 ${fromVersion} 迁移到版本 ${toVersion}。有哪些破坏性变更,以及我需要遵循哪些步骤?`,
        },
      }],
    }
  },
})
```

### 添加自定义处理器

处理器允许你创建独立的 MCP 端点，各自拥有自己的工具、资源和提示词。这适用于在不同路由上暴露不同能力的场景。

例如，你可以拥有：

- `/mcp` - 主文档 MCP 服务器
- `/mcp/migration` - 专门用于迁移辅助的 MCP 服务器

```ts [server/mcp/migration.ts]
import { z } from 'zod'

const migrationTool = defineMcpTool({
  name: 'migrate-v3-to-v4',
  description: '将代码从版本 3 迁移到版本 4',
  inputSchema: {
    code: z.string().describe('要迁移的代码'),
  },
  handler: async ({ code }) => {
    // 迁移逻辑
    return {
      content: [{ type: 'text', text: migratedCode }],
    }
  },
})

export default defineMcpHandler({
  route: '/mcp/migration',
  name: '迁移助手',
  version: '1.0.0',
  tools: [migrationTool],
})
```

### 覆盖内置工具

你可以在项目中创建同名工具，来覆盖默认的 `list-pages` 或 `get-page` 工具：

```ts [server/mcp/tools/list-pages.ts]
import { z } from 'zod'

export default defineMcpTool({
  description: '自定义的 list pages 实现',
  inputSchema: {
    locale: z.string().optional(),
    category: z.string().optional(),
  },
  handler: async ({ locale, category }) => {
    const pages = await getCustomPageList(locale, category)
    return {
      content: [{ type: 'text', text: JSON.stringify(pages) }],
    }
  },
})
```
