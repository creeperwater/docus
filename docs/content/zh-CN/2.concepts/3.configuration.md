Docus 允许你通过 Nuxt 提供的 [app.config.ts](https://nuxt.com/docs/4.x/directory-structure/app/app-config) 文件来配置文档。

::warning
如果要覆盖应用配置，你需要先设置 `nuxt.config.ts`。如果没有现成的 Nuxt 配置文件，更改将不会生效。
::

## SEO

技术性 SEO 既繁琐又枯燥。Docus 提供了一套可靠的默认配置，开箱即用，同时让你能够完全自定义 SEO 元数据，从页面标题到社交分享图片。

### 元数据

Docus 提供灵活的 `SEO` 元数据配置，让你可以轻松地进行全局覆盖或按页面覆盖。

#### 全局配置

在 `app.config.ts` 中为整个文档定义默认的 `SEO` 元信息。对于没有像下一节那样在 frontmatter 中自行指定这些值的页面，它们将作为兜底值使用。

你也可以在 `nuxt.config.ts` 文件中配置 `site.name` 的值，默认值取自 `package.json` 的 name。

::code-group
```ts [app.config.ts]
export default defineAppConfig({
  seo: {
    // 默认为 `%s - ${site.name}`
    titleTemplate: '',
    // 默认为 package.json 的 name
    title: '',
    // 默认为 package.json 的 description
    description: ''
  },
})
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  site: {
    name: 'Docus',
  },
})
```
::

#### 按页面配置

`content/` 目录中的每个 Markdown 文件都以 frontmatter 块 (`---`)开头。你可以使用 `seo` 键为每个页面定义 `SEO` 元数据：

```md [content/concepts/configuration.md]
---
seo:
  title：'配置'
  description：'通过 Nuxt 应用配置文件自定义你的 Docus 文档。'
---

<!-- 页面内容 -->
```

::tip{to="/zh-cn/concepts/edition#frontmatter"}
关于 frontmatter 的更多细节，请参阅版本指南。
::

### 结构化数据

Docus 通过 [`nuxt-schema-org`](https://nuxtseo.com/docs/schema-org) 输出 [JSON-LD](https://json-ld.org):

- 每个页面都包含 `WebSite` 和 `WebPage`
- 文档页面还包含 `TechArticle` 和 `BreadcrumbList`

搜索引擎和 AI 代理可以读取这些数据，无需解析你的页面标记即可了解页面的内容。

落地页还可以描述你的站点*本身*是什么。添加 `seo.schema` 后，Docus 会输出一个关联图谱，包含你的产品及其背后的组织：

```ts [app.config.ts]
export default defineAppConfig({
  seo: {
    schema: {
      type: 'SoftwareApplication',
      applicationCategory: 'DeveloperApplication',
      price: 0,
      sameAs: [
        'https://github.com/nuxt-content/docus',
        'https://www.npmjs.com/package/docus',
      ],
      organization: {
        name: 'Nuxt',
        url: 'https://nuxt.com',
        logo: '/logo/logo-dark.svg',
        sameAs: ['https://github.com/nuxt'],
      },
    },
  },
})
```

| 字段 | 描述 |
| --- | --- |
| `type` | 站点的类型：`SoftwareApplication`、`Product`、`Organization` 或 `Person`。如果不设置，则只输出 `WebSite`。 |
| `sameAs` | 官方资料页 URL(GitHub、npm、X、LinkedIn)，用于在不同来源之间统一你的身份信息。 |
| `applicationCategory` | 应用类别，默认为 `DeveloperApplication`。仅适用于 `SoftwareApplication`。 |
| `operatingSystem` | 运行平台，默认为 `Web`。仅适用于 `SoftwareApplication`。 |
| `price` | 应用价格。设置为 `0` 表示免费。仅适用于 `SoftwareApplication` 和 `Product`。 |
| `priceCurrency` | `price` 的 ISO 4217 货币代码，默认为 `USD`。 |
| `organization` | 站点的发布者，以关联的 `Organization` 形式输出。接受 `name`、`url`、`logo`、`sameAs`、`address` 和 `contactPoint`。 |
| `organization.parentOrganization` | 发布者所属的公司，嵌套在发布者的 `Organization` 内部。 |

::note
该模块的每个 `schemaOrg` 选项都可以在你的 `nuxt.config.ts` 中使用。如果不设置 `seo.schema`，落地页将保留其 `WebSite` 和 `WebPage` 节点。
::

### **社交分享 (OG) 图片**

当你在社交媒体或聊天平台上分享文档链接时，链接会被**展开预览**，也就是展示所链接内容的概览 (包括标题、描述和图片)。这一切都由 **Open Graph Protocol** 驱动。

#### 文档页面

我们在底层使用 [Nuxt OG Image](https://nuxtseo.com/docs/og-image/getting-started/introduction)，根据提供的标题和描述为每个文档页面生成 OG 图片。例如，当前页面的 OG 图片为：

![文档页面的 og 图片](https://docus.dev/_og/s/c_Docs,headline_Core+Concepts,title_Configuration,description_Customize+your+Docus+documentation+from+Nuxt+application+configuration+file.,p_Ii9lbi9jb25jZXB0cy9jb25maWd1cmF0aW9uIg.png)

#### 落地页

与文档页面相同，落地页也使用同样的 OG 图片生成器，基于提供的标题和描述生成图片。

![落地页的 og 图片](https://docus.dev/_og/s/c_Landing,title_Write+beautiful+docs+with+Markdown,description_Ship+fast+flexible+and+SEO-optimized+documentation+with+beautiful+design+out+of+the+box.+Docus+brings+together+the+best+of+the+Nuxt+ecosystem.+Powered+by+Nuxt+UI.,p_Ii9lbiI.png)


#### 覆盖 OG 图片

由于 Docus 是一个 [Nuxt 层](https://nuxt.com/docs/guide/going-further/layers)，你可以在自己的 `components/OgImage/` 目录中创建同名文件，来覆盖文档页或落地页的 OG 图片。

```
components/
  OgImage/
    Docs.takumi.vue     # 覆盖文档页面的 OG 图片
    Landing.takumi.vue  # 覆盖落地页的 OG 图片
```

你的组件会通过 props 接收 `title`、`description` 和 `headline`(仅文档页面)，并可以使用 [Takumi 渲染器](https://nuxtseo.com/docs/og-image/guides/renderers)支持的任何 Tailwind CSS 或行内样式。

### 站点地图

Docus 使用 [`@nuxtjs/sitemap`](https://nuxtseo.com/docs/sitemap) 在 `/sitemap.xml` 生成站点地图，列出每个内容页面。在多语言站点上，它会变成一个站点地图索引，每个语言对应一个站点地图。该模块的每个 `sitemap` 选项都可以在你的 `nuxt.config.ts` 中使用。

#### 排除页面

要将某个页面从站点地图中排除，在其 frontmatter 中添加 `sitemap: false`:

```md [content/draft-page.md]
---
sitemap: false
---

此页面不会出现在站点地图中。
```

#### 站点 URL

为了让站点地图中的 URL 正确无误，请设置 `NUXT_SITE_URL` 环境变量：

```bash
NUXT_SITE_URL=https://your-site.com
```

## 页头

配置文档站点的 `title` 或 `logo`:

```ts [app.config.ts]
export default defineAppConfig({
  header: {
    title: '',
    logo: {
      light: '',
      dark: '',
      alt: '',
    },
  },
})
```

### 品牌资源

你可以为 logo 配置额外的品牌资源。在页头中右键点击 logo，会打开一个包含复制和下载操作的上下文菜单。

```ts [app.config.ts]
export default defineAppConfig({
  header: {
    title: '我的项目',
    logo: {
      light: '/logo/logo-dark.svg',
      dark: '/logo/logo-light.svg',
      alt: '我的项目 Logo',
      wordmark: {
        light: '/logo/wordmark-dark.svg',
        dark: '/logo/wordmark-light.svg',
      },
      favicon: '/favicon.svg',
      brandAssetsUrl: 'https://example.com/brand',
    },
  },
})
```

| 字段                           | 描述                                                                     |
| ------------------------------ | ------------------------------------------------------------------------ |
| `logo.wordmark.light` / `dark` | 每种颜色模式下使用的完整文字标识 (图标 + 文字)。                         |
| `logo.display`                 | 页头中显示的变体：`'logo'`(默认) 或 `'wordmark'`。                      |
| `logo.class`                   | logo 图片上附加的 CSS 类 (例如 `'h-8'`)。                                |
| `logo.favicon`                 | favicon 文件的路径。默认为 `/favicon.ico`。                              |
| `logo.brandAssetsUrl`          | 品牌资源页面的链接，以菜单项形式显示。                                   |

当 logo 是 SVG 时，上下文菜单会提供**复制 logo** 和**复制文字标识**操作，复制出使用 `currentColor` 填充的原始 SVG，可直接粘贴到 Figma 或任何设计工具中。对于非 SVG 格式 (PNG 等)，仅提供下载操作。

## 颜色模式

默认情况下，Docus 在页头和页脚中包含一个颜色模式切换按钮，允许用户在浅色和深色模式之间切换。

如果你的文档只使用一种主题，可以通过设置 `colorMode` 选项来强制指定：

```ts [app.config.ts]
export default defineAppConfig({
  docus: {
    colorMode: 'dark'
  }
})
```

| 值 | 行为 |
| --- | --- |
| `''`(默认) | 跟随系统偏好，并显示切换按钮 |
| `'light'` | 强制浅色模式，隐藏切换按钮 |
| `'dark'` | 强制深色模式，隐藏切换按钮 |

### 键盘快捷键

当颜色模式切换按钮可见时，按 :kbd{value="D"} 可在浅色和深色模式之间切换。

你可以在 `app.config.ts` 中自定义或禁用此快捷键：

```ts [app.config.ts]
export default defineAppConfig({
  docus: {
    shortcuts: {
      toggleColorMode: 'd', // 默认
    },
  },
})
```

将 `toggleColorMode` 设置为空字符串即可禁用该快捷键。快捷键格式 (`meta_d`、`ctrl_shift_p` 等)请参阅[助手](/zh-cn/ai/assistant#keyboard-shortcuts)页面。

当强制指定了颜色模式后，页头和页脚中的切换按钮会被隐藏，命令面板中的颜色模式相关命令也会被移除。

## 导航

### 子导航

对于内容板块众多的文档站点，你可以启用子导航，将顶层内容文件夹拆分为多个板块，并将左侧边栏过滤为仅显示当前板块的页面。

有两种显示模式可用：

- **`header`** — 在页头下方渲染一个次级标签栏 (仅限桌面端，移动端使用抽屉)
- **`aside`** — 在左侧边栏顶部渲染板块锚点 (移动端使用抽屉)


```ts [app.config.ts]
export default defineAppConfig({
  navigation: {
    sub: 'header', // 或 'aside'
  },
})
```

:video{src="https://res.cloudinary.com/nuxt/video/upload/v1773263594/docus/subnav_idh2ae.mp4"}

::note
标签页会根据 `content/` 中的顶层文件夹自动生成。每个文件夹的标题和图标从其 `.navigation.yml` 文件中读取。
::



## 搜索

Docus 内置了由 [Nuxt UI ContentSearch](https://ui.nuxt.com/docs/components/content-search) 驱动的全文搜索。默认情况下，它使用客户端 [Fuse.js](https://www.fusejs.io/) 过滤，会预先加载所有搜索板块。

### FTS5 全文搜索

你可以切换到 [SQLite FTS5](https://content.nuxt.com/docs/utils/use-search-collection)，获得更快的索引式搜索，并内置摘要高亮。它使用 SQLite WASM 在浏览器中构建 FTS5 索引，只在输入查询时才执行搜索，而不是预先加载所有板块。

```ts [app.config.ts]
export default defineAppConfig({
  search: {
    fts: true
  }
})
```

| 模式 | 索引 | 速度 | 容错能力 | 预加载内容 |
| --- | --- | --- | --- | --- |
| Fuse.js (默认) | 内存中 JS 扫描 | 每次查询 O(n) | 完全模糊匹配 | 加载所有板块 |
| FTS5 | SQLite 倒排索引 | O(log n) 查找 | 仅前缀匹配 | 无 |

## 社交链接

在页脚中添加你的社交媒体链接，使用 `Record<string, string>`，其中键名需与 [Simple Icons](https://simpleicons.org/) 图标库中的图标匹配。

```ts [app.config.ts]
export default defineAppConfig({
  socials: {
    x: 'https://x.com/nuxt_js',
    discord: 'https://discord.com/invite/ps2h6QT',
    nuxt: 'https://nuxt.com',
  }
})
```

## 目录

你可以自定义每个页面右侧边栏中的目录。

```ts [app.config.ts]
export default defineAppConfig({
  toc: {
    // 重命名目录的标题
    title: '本页内容',
    // 在目录底部添加一个区块
    bottom: {
      title: '社区',
      links: [{
        icon: 'i-lucide-book-open',
        label: 'Nuxt UI 文档',
        to: 'https://ui.nuxt.com/getting-started/installation/nuxt',
        target: '_blank'
      }]
    }
  }
})
```

## 语言

对于单语言文档 (不使用完整的 `@nuxtjs/i18n` 模块)，你可以通过 `app.config.ts` 配置语言：

```ts [app.config.ts]
export default defineAppConfig({
  docus: {
    locale: 'fr', // 默认:'en'
  }
})
```

这会设置以下内容的语言：

- UI 组件的翻译
- `<html>` 标签上的 `lang` 和 `dir` 属性
- Docus 内置的界面文案

::tip{to="/zh-cn/concepts/internationalization"}
如需支持语言切换的多语言文档，请参阅[国际化指南](/zh-cn/concepts/internationalization)。
::

## GitHub 集成

Docus 会读取你的 `.git/` 文件夹，获取仓库的 `url` 和 `branch`，用于添加：

- 页头和页脚中的 GitHub 图标
- 每个页面页脚中的 `Edit this page`(编辑此页) 和 `Report an issue`(报告问题) 链接。

你可以在 `app.config.ts` 文件中添加以下配置，来自定义文档应用的 `url`、`branch` 和 `rootDir`:

```ts [app.config.ts]
export default defineAppConfig({
  github: {
    url: 'https://github.com/nuxt-content/docus',
    branch: 'main',
    rootDir: 'docs'
  }
})
```

如果你不想使用 GitHub，可以将 `github` 键设置为 `false` 来禁用 GitHub 集成。

```ts [app.config.ts]
export default defineAppConfig({
  github: false
})
```

这些配置也可以在 Studio 编辑器中完成，快来试试吧！
::
