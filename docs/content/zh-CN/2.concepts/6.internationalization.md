Docus 引入了基于 `@nuxtjs/i18n` 模块的**原生国际化支持**，让你能够以多种语言创建文档，并自动处理路由和内容管理。

## 特性

- **内置 i18n 模块**：与 `@nuxtjs/i18n` 原生集成
- **动态语言路由**：自动为 URL 添加语言代码前缀 (`/en/docs`、`/fr/docs`)
- **按语言划分的内容集合**：为每种语言单独管理内容
- **语言切换器**：内置组件，用于在不同语言之间切换
- **单语言配置**：通过 `app.config.ts` 为单语言站点提供简单的语言配置

## 单语言配置

如果你只使用一种语言编写文档 (不使用完整的 `@nuxtjs/i18n` 模块)，可以通过 `app.config.ts` 配置语言。这对于设置 UI 组件的语言以及本地化内置文案非常有用。

```ts [app.config.ts]
export default defineAppConfig({
  docus: {
    locale: 'fr', // 设置你的语言(默认:'en')
  }
})
```

## 多语言设置

对于多语言文档，请使用下文所述的完整 `@nuxtjs/i18n` 集成。

### 在现有项目中设置

要在你的 Docus 项目中启用 i18n，请将 `@nuxtjs/i18n` 模块添加到 `nuxt.config.ts` 中，并定义你的语言：

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', name: 'English' },
      { code: 'fr', name: 'Français' },
    ],
  }
})
```

::warning
Docus 会将 `@nuxtjs/i18n` 的策略覆盖为 `prefix`。
::

## 使用 i18n 模板创建新项目

创建新项目时，你可以选择 i18n 模板，获得预先配置好的国际化支持：

```bash [Terminal]
npx create-docus my-docs -t i18n
```

## 目录结构

启用 i18n 后，请在 `content/` 目录中按语言组织你的内容：

```bash
content/
├── en/                    # 英文内容
│   ├── index.md          # 英文首页
│   ├── getting-started/
│   │   ├── installation.md
│   │   └── configuration.md
│   └── guide/
│       └── advanced.md
├── fr/                    # 法文内容
│   ├── index.md          # 法文首页
│   ├── getting-started/
│   │   ├── installation.md
│   │   └── configuration.md
│   └── guide/
│       └── advanced.md
```

::warning
每种语言都应保持相同的目录结构，以确保各语言之间的导航一致。
::

## 带地区的语言代码

你可以使用包含地区的语言代码，例如 `zh-TW`、`zh-CN` 或 `pt-BR`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', name: 'English' },
      { code: 'zh-TW', name: '繁體中文' },
    ],
  }
})
```

- **URL** 使用小写代码，例如 `/zh-tw/getting-started/installation`。
- **内容文件夹**可以保留原始大小写：`content/zh-TW/` 和 `content/zh-tw/` 均可。
- **`<html lang>`** 保留地区标签，例如 `zh-TW`。

::warning
在任何引用语言代码的地方 (例如内部链接) 都请使用小写代码 (`zh-tw`)。Docus 始终会将访客重定向到小写 URL。
::

## 语言回退

对于 `content/` 目录中不存在的语言，Docus 会发出警告并跳过。缺失的语言不会被注册。

::tip
当你扩展 Docus 并在站点的其余部分使用 `@nuxtjs/i18n`，但只希望文档支持其中一部分语言时，这一点尤其有用。
::

Docus 会从你的 nuxt 配置中检测语言：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  i18n: {
    locales: ['en', 'fr', 'ja'],
    defaultLocale: 'en'
  }
})
```

但只会根据你的 `content/` 文件夹结构进行注册：

```bash
content/
├─ en/           # 已注册 ✅
├─ fr/           # 已注册 ✅(如果存在)
└─ ja/           # 已跳过 🚫(如果缺失)
```

如果用户请求了缺失的文档语言，Docus 会重定向到**默认语言**。

::warning
你必须在 i18n 配置中设置 `defaultLocale`，并确保它存在于 `content/<defaultLocale>` 下
::
